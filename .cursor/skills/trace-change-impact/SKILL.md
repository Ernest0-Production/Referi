# Оценка зоны влияния правки

## When to use

Перед переименованием, сменой контракта, правкой общего компонента или «где ещё это всплывёт».

## Steps

1. Сформулируй символ, строку UI или маршрут, который меняется.
2. Найди все вхождения в репозитории (поиск по идентификатору, тексту копирайта, пути файла).
3. Отметь границы слоёв: UI, клиентские хуки, серверные роутеры, схема/валидация, тесты.
4. Проверь публичные контракты (типы экспортов, API, env) на согласованность.
5. Реши минимальный набор файлов для одной атомарной правки; вынеси риск «сломать соседей» в отдельный шаг или вопрос пользователю.
6. После правки повтори поиск по старым строкам, чтобы не осталось «хвостов».
7. Запусти релевантные проверки проекта для затронутых путей.
