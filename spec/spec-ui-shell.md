# UI shell (навигация и страницы)

Нормативное описание оболочки интерфейса после выравнивания с публичным каталогом вакансий.

## Компоненты шапки

| Область | Компонент | Файл |
|--------|-----------|------|
| Публичные страницы (каталог, деталь вакансии, login, регистрация, mock-оплата, pay без вложенного layout) | `PublicHeaderNav` | [`src/components/PublicHeaderNav.tsx`](../src/components/PublicHeaderNav.tsx) |
| Кабинет `/dashboard/*` | `DashboardHeaderNav` + layout | [`src/components/DashboardHeaderNav.tsx`](../src/components/DashboardHeaderNav.tsx), [`src/app/dashboard/layout.tsx`](../src/app/dashboard/layout.tsx) |
| Модерация `/admin/*` | `AdminHeaderNav` + layout | [`src/components/AdminHeaderNav.tsx`](../src/components/AdminHeaderNav.tsx), [`src/app/admin/layout.tsx`](../src/app/admin/layout.tsx) |

Правило: **первичная навигация задаётся в `layout.tsx` соответствующего сегмента**, а не дублируется в каждой `page.tsx`. В шапках кабинета и админки доступны переключатель темы (`ThemeToggle`) и выход из аккаунта (через меню профиля).

## Поверхность страницы и токены

Фон «страницы приложения» (в т.ч. каталог и кабинет) задаётся CSS-переменной **`--app-page-surface`** в [`src/app/globals.css`](../src/app/globals.css). Акценты поиска и CTA PRO в шапке: **`--app-search-accent-*`**, **`--app-nav-cta-*`**.

Тема: `next-themes` в корневом [`src/app/layout.tsx`](../src/app/layout.tsx); семантические классы Tailwind (`bg-background`, `text-muted-foreground`, `border-border`, компоненты shadcn) предпочтительнее сырых `gray-*`.

## Формы

Клиентские формы в кабинете и жалобах используют **`FieldGroup` / `Field` / `FieldLabel`** из [`src/components/ui/field.tsx`](../src/components/ui/field.tsx), **`Input`**, **`Textarea`**, **`Select`**, **`Button`**, **`Alert`** — без вертикальных отступов через `space-y-*` (вместо них `flex flex-col gap-*` или встроенные зазоры `FieldGroup`).

В боковой панели фильтров каталога вакансий ([`src/app/vacancies/VacancyFilters.tsx`](../src/app/vacancies/VacancyFilters.tsx)) выбор **специализации** задаётся одиночным **`Select`** (значение «Любая» снимает фильтр по специализации); грейд и формат работы — группы переключателей. Состояние фильтров и поиска живёт в клиентском каталоге ([`VacancyCatalogClient.tsx`](../src/app/vacancies/VacancyCatalogClient.tsx)); при изменении фильтров **строка адреса не обновляется**; карточка фильтров **остаётся смонтированной** при смене параметров (ввод «Зарплата не ниже» — отдельный блок с `key` по закоммиченному значению из `currentParams`, без эффекта синхронизации). Идентификатор выбранного в сайдбаре **сохранённого пресета** (для подписи в `Select` и режима «Обновить») держится в состоянии каталога и не сбрасывается при расхождении текущих полей со снимком пресета, пока пользователь не очистит выбор или не сменит пресет. Круглая кнопка **сброса фильтров** (RotateCcw) сбрасывает параметры каталога **и** снимает выбор пресета в `Select` до placeholder «Выберите фильтр» (флаг в каталоге плюс перемонтирование `Select` по счётчику — иначе Radix может оставить старую подпись при `value: undefined`). Пока набор полей пресета (специализация, грейд, формат, зарплата, сортировка, строка поиска) **совпадает** со снимком выбранного пресета, вместо «Обновить» и меню действий показывается одна кнопка **«Удалить»** (`variant="destructive"`). После **любого расхождения** снова показываются **«Обновить»** и выпадающее меню (создание нового пресета, удаление). Для полей с несколькими значениями через запятую сравнение по **набору** допустимых значений, порядок токенов в строке не влияет. Первый запрос страницы по-прежнему может использовать `searchParams` на сервере только для начальной гидратации. Внутреннее представление специализации (и в сохранённых пресетах) по-прежнему может быть строкой с несколькими значениями через запятую; при нескольких значениях в списке показывается служебный пункт до выбора одной специализации или «Любая».
