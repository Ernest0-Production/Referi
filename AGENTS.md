## Learned User Preferences

- Обновлять долговременную память проекта через поток continual-learning (memory-updater), а не править `AGENTS.md` параллельно в том же сценарии без необходимости.
- Ожидать рабочую сборку, осмысленное снятие TODO и исправление предупреждений без массовых `eslint-disable` / заглушек.
- Для приёмки важны ручной прогон на localhost и совместимость с локальным Docker/env из `.env.example`.
- `.env` в воркспейсе всегда есть (в `.gitignore`). Меняя для локальной разработки переменные окружения, секреты или ключи фичефлагов, править **оба** файла: `.env.example` и `.env`, не только шаблон.
- Общение с ассистентом в чате — на русском; код, UI-копирайт и доки — по языку проекта и принятым в репозитории конвенциям.
- Схемы в markdown-файлах репозитория предпочтительно оформлять в **Mermaid**, а не ASCII-блоками; исключение — **tree-view** (например обзор дерева проекта), где ASCII уместен.
- При вопросах «сделано ли по PRD/ROADMAP» опираться на **фактическую реализацию в коде**, а не на формальные отметки выполненности в markdown-документах; не принимать «MVP-послабления» и не подменять полноту поведения риторикой «после релиза» вместо фактической реализации.
- В каталоге вакансий не добавлять анимации переходов между состояниями кнопок пресетов/футера фильтров — предпочтительны статичные состояния; «кастомная» анимация через shadcn ухудшает UX.
- Регистрационный сбор при фиксированной продуктовой сумме — константа в рублях в бизнес-правилах/коде, без отдельного сервиса динамической конвертации по курсу ЦБ, пока явно не требуется иное в PRD.
- Не сводить «чистоту» проекта только к ESLint: учитывать `**npm run typecheck`** и замечания TypeScript в панели Problems в IDE — они могут не совпадать с выводом `npm run lint` по корню.
- Запуск ESLint — через `**npm run lint`** или `**./node_modules/.bin/eslint**` из корня после `npm ci`; голый `**npx eslint**` вне корректно установленного проекта может подтянуть другую версию ESLint и давать иной результат.
- При синхронизации `docs/` и `spec/` в рамках задачи не дополнять документы «обнаруженными в коде» расхождениями, если эти места не менялись в текущей сессии работы — отражать только объём фактически выполненных в ней изменений.

## Learned Workspace Facts

- Воркеры BullMQ (`startSLAWorker`, `startPaymentWorker`) стартуют из `src/instrumentation.ts` в `register()` при `NEXT_RUNTIME === "nodejs"`, `CI !== "true"` и `**ENABLE_BULLMQ_WORKERS === "true"**` (значение обязательно в окружении и валидируется в `src/env.ts`). В `docker-compose.yml` для сервиса `app` задано `ENABLE_BULLMQ_WORKERS=true`; в `.env.example` по умолчанию `false` — воркеры не поднимаются, пока не выставить `true`.
- В `slaWorker` и `paymentWorker` используются ленивое создание очередей и в `src/lib/redis.ts` у IORedis включён `lazyConnect`, чтобы при `next build` не было подключения к Redis и ошибок `ECONNREFUSED`.
- SLA в очереди завязаны на сценарии: первый отклик, дедлайн оплаты после подтверждения намерения, передача резюме, SLA подтверждения отмены соискателем, дедлайн решения компании.
- Платёжная очередь обрабатывает capture после принятия оффера, возвраты, payout и автопродление PRO ЮKassa (`subscription-renewal` на конец оплаченного периода, `subscription-renew-retry` при неудаче; планирование в `subscriptionRenewalScheduler.ts`, обработка в `paymentWorker`); для выплат используется `User.yookassaPayoutDestination`, для локального мока — `YOOKASSA_PAYOUT_MOCK_WALLET`. События ЮKassa — модуль `yookassaWebhookHandlers`; мок-поток: `/pay/mock` и `POST /api/pay/mock-complete`; при `FEATURE_REAL_PAYMENTS=true` HTTP-вебхук проверяет Basic Auth из `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY`.
- Эскроу по заявкам с вознаграждением в коде и в `docs/`/`spec/` ведётся через **ЮKassa Safe deal** (HTTP-слой сделок); термин **Escrow** — внутреннее имя защищённой оплаты (деньги удерживает провайдер). Регистрация, подписка PRO и разовый токен отклика остаются обычными платежами Payments API — см. `spec/spec-data-payments-escrow.md`.
- Исходящих email-уведомлений из сервиса нет; опциональная связь с модерацией — публичная ссылка в клиенте (`NEXT_PUBLIC_MODERATION_CONTACT_URL`).
- Клиент Prisma создаётся в `src/lib/prisma.ts` с драйвером PostgreSQL через `@prisma/adapter-pg` и пул `pg` (требование Prisma 7 для engine type client). Если IDE показывает «нет экспорта `Prisma`» из `@prisma/client`, сверять наличие сгенерированного `node_modules/.prisma/client` после `prisma generate` и при необходимости тип колбэка `$transaction` задавать через вывод из `typeof prisma` или общий helper в `src/lib/`.
- Правила `.cursor/rules`: «органичный редизайн» — без обратной совместимости и без комментариев о прошлой реализации; после изменений `schema.prisma` в агентском режиме локальную БД приводят к согласованному состоянию (сброс/полное применение схемы), без инкрементальных миграций ради совместимости. При изменениях статуса фич или публичного контракта обновлять `docs/`, `spec/` и `docs/ROADMAP.md` в той же единице работы (`documentation-sync.mdc`).
- Каталог вакансий (`[VacancyCatalogClient](src/app/vacancies/VacancyCatalogClient.tsx)`): фильтры, поиск, сортировка и страница в **локальном состоянии**; список — `**trpc.vacancies.list`** (первая отрисовка с `**searchParams`** на SSR); **строка адреса при смене фильтров и поиска не меняется**; пагинация — кнопки; колонка фильтров — боковая с брейкпоинта `**md` (768px)**; лента каталога — `**/`**; детальная страница вакансии — `**/vacancies/[id]**`; сохранённые наборы — `**vacancySearchPresets**` (list/create/update/delete); в сайдбаре выбор сохранённого набора — горизонтальный ряд вкладок `**Tabs**` ([`tabs.tsx`](src/components/ui/tabs.tsx)), не `**Select**`; у `**TabsContent**` в этом файле нет базового `**flex-1**` (чтобы блок пресетов не раздувал высоту и не давал лишний вертикальный скролл); ряд `**TabsList**` пресетов — `**overflow-y-hidden**`, у триггеров задана фиксированная высота; выбранный пресет опирается на состояние каталога (`**activeVacancyPresetId**`, carry последнего совпадения с JSON пресета); `[VacancyFilters](src/app/vacancies/VacancyFilters.tsx)` **не** перемонтируется `key`’ом на каждый параметр; поле «Зарплата не ниже» — отдельный блок с `**key` по закоммиченному `salaryFrom` и `salaryCurrency` из родителя**; без суммы валюта в параметрах каталога и в пресете не задаётся, чтобы при смене пресета/сброса подставлялось актуальное значение без `useEffect`; сброс фильтров кнопкой **RotateCcw** выставляет `**vacancyPresetSidebarCleared`** и увеличивает `**savedPresetSelectLayoutKey`**, чтобы блок вкладок пресетов перемонтировался и показывал «Не выбран» до нового выбора (и не подставлял `matchedPresetId` при пустых параметрах; Radix не всегда обновляет вид без перемонтирования); выбор пресета — `**onPickSavedVacancyPreset**`; при **совпадении** полей пресета со снимком в футере фильтров — только кнопка **«Удалить»** (destructive), при **расхождении** — **«Обновить»** и выпадающее меню; спиннеры у `**input[type="number"]`** скрыты в `**src/app/globals.css`**; иконки фильтров — `**@tabler/icons-react**`. `[VacancyListChrome](src/app/vacancies/VacancyListChrome.tsx)`: при refetch списка не вешать `**disabled**` на кнопку «Искать» из‑за `**listBusy**` — иначе у корня `**InputGroup**` срабатывают классы `**has-disabled**` и полоса поиска визуально «мерцает»; индикатор загрузки в слоте иконки — только при `**isPending**` (отправка поиска). `**vacancies.getById**` и `**/vacancies/[id]**` валидируют `**id**` через `**z.string().uuid()**`; в сиде — RFC‑валидные UUID (нулевые/невалидные версии → **404**).
- shadcn `**Select`**: на `**SelectContent`** — `**position="popper"**` (не дефолт `**item-aligned**` без явной причины), чтобы списки не обрезались в сайдбарах, диалогах и скроллящихся контейнерах.
- Шапки публичного кабинета и админки (`[PublicHeaderNav](src/components/PublicHeaderNav.tsx)`, `[DashboardHeaderNav](src/components/DashboardHeaderNav.tsx)`, `[AdminHeaderNav](src/components/AdminHeaderNav.tsx)`): аватар — `**AvatarImage**` с URL из `**userAvatarImageUrl**` (`[src/lib/userAvatarUrl.ts](src/lib/userAvatarUrl.ts)`): приоритет `**session.user.image**` (в JWT сохраняется как `**token.picture**` из OAuth в колбэках `[src/lib/auth.ts](src/lib/auth.ts)`), иначе `**https://github.com/{githubLogin}.png**`; `**AvatarFallback**` — инициалы.
- Окружение для прикладного кода валидируется в `src/env.ts` (Zod): обязательные переменные задаются явно, без «тихих» подстановок в модулях; при несоответствии контракту процесс падает при старте (fail-fast). Полный перечень и комментарии — в `.env.example` и README. Если `node_modules/.bin/next` или `tsc` оказались обычными файлами вместо симлинков и падают с неверными относительными путями, обычно помогает чистая переустановка: `rm -rf node_modules && npm ci`.
